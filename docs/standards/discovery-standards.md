# Discovery Standards

## Scope

Applies to Founder and PM work on goals, user insight, scope boundaries, and value judgment.

## Hard Rules

1. Goals and non-goals must be explicit. A wishlist cannot be treated as the MVP.
2. Target users, core scenarios, and failure scenarios must be documented.
3. The document must explain why the work is needed now.
4. Key conclusions must trace back to `References and Evidence` or internal research notes.
5. If high-impact ambiguity remains, the work may not move directly into design.

## Recommended Rules

1. Describe the project goal with a one-sentence value proposition whenever possible.
2. For each core scenario, write a success standard and a rejection boundary.
3. Record technical, business, and compliance constraints separately.

## Minimum Acceptance

1. `problem_statement`, `target_persona`, and `core_use_case` are non-empty.
2. At least one acceptance metric can be used for Gate 0 judgment.
3. Risks and non-goals put explicit boundaries on implementation scope.
