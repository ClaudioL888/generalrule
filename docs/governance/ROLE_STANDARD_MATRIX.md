# Role Standard Matrix

## Purpose

Defines which long-term standards each role must bind during execution and handoff, so the same role does not operate under different standards each time.

## Matrix

1. `Founder`
- Standards: `docs/NORMS.md`, `docs/standards/discovery-standards.md`, `docs/standards/documentation-standards.md`
- Primary outputs: goals/non-goals, key tradeoffs

2. `PM`
- Standards: `docs/standards/discovery-standards.md`, `docs/standards/documentation-standards.md`
- Primary outputs: user stories, acceptance metrics, boundary conditions

3. `Architect`
- Standards: `docs/standards/design-standards.md`, `docs/standards/security-standards.md`, `docs/standards/observability-standards.md`
- Primary outputs: interfaces, models, security boundaries, observability

4. `Planner`
- Standards: `docs/standards/planning-standards.md`, `docs/standards/testing-standards.md`
- Primary outputs: task breakdown, test points, acceptance criteria

5. `Dev`
- Standards: `docs/standards/coding-standards.md`, `docs/standards/testing-standards.md`, `docs/standards/documentation-standards.md`
- Primary outputs: implementation, test evidence, documentation sync

6. `QA`
- Standards: `docs/standards/testing-standards.md`, `docs/standards/documentation-standards.md`
- Primary outputs: regression conclusion, uncovered items, risk list

7. `Reviewer`
- Standards: `docs/standards/documentation-standards.md`, `docs/standards/security-standards.md`
- Primary outputs: risk judgment, blockers, compliance conclusion

8. `Release-Ops`
- Standards: `docs/standards/release-standards.md`, `docs/standards/observability-standards.md`, `docs/standards/security-standards.md`
- Primary outputs: release notes, rollback plan, monitoring checks

9. `Growth / Content-Growth`
- Standards: `docs/standards/documentation-standards.md`, `docs/metrics/ENGINEERING_METRICS.md`
- Primary outputs: content assets, AARRR mapping, growth feedback
